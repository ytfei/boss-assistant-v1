# Boss 求职助手 · 开源版

> **一个完全本地运行的 Boss 直聘求职效率工具。** 抓岗位、拆 JD、算匹配、排优先级、写话术、回消息 —— 全部在你的浏览器里完成。
>
> 没有服务端，没有注册，没有埋点；岗位、简历、分析结果只存在你自己的电脑上。
> **不填任何 AI 凭证也能用** —— 薪资分布、技能词频、匹配三档、雷区预警都是本地规则计算；想更进一步，就接入你自己喜欢的任意大模型。

## 求职时，你是不是也这样

- 岗位刷了几十个上百个，看花眼，来回对比全靠记忆和截图；
- 每份 JD 都长得差不多，到底哪些技能是**真要求**、哪些只是**加分项**，说不清楚；
- 简历投出去没回音，却不知道自己到底和这个岗位**差在哪**；
- HR 一句「期望薪资多少」就慌了 —— 报低了亏，报高了黄；
- 每次打招呼都要现编开场白，还怕写出「本人性格开朗、吃苦耐劳」这种正确的废话。

**Boss 求职助手就是为了把这些环节自动化。** 它在你正常浏览 Boss 直聘时旁路工作，把零散、重复、靠感觉的求职动作，变成一张可筛选、可对比、可复用的表格和一份有依据的建议。

## 它能为你做什么

### 岗位自动进表，不再靠截图

在列表页正常滚动、翻页，插件就**旁路捕获**每一个岗位（公司、职位、薪资、城市、经验、学历、技能标签、HR 在线状态…），自动去重、落盘、成表。

- 三种数据来源逐级降级：**接口旁路 > DOM 兜底 > 你点开卡片时的详情请求**，几乎不会漏；
- 关掉页面也不会丢 —— 历史记录存在本地，下次打开面板自动恢复；
- 一键导出 **CSV**（含 JD 职责/要求/加分项全文与岗位链接），拿去做自己的表格或归档。

### 一键解析全部 JD

点一下「解析全部 JD」，插件会逐条补齐 JD 全文，并**本地规则拆成「岗位职责 / 能力要求 / 加分项」**三段，表格里直接展开阅读。

- 请求间隔 **0.5–2 秒随机**，失败自动**指数退避**，连续出错自动暂停；
- 限额保护：**单页 30 条 / 单日 200 条**，把风控风险压在最低；
- 浅绿=已解析、浅灰=未解析，状态一眼可见。

### 批次画像：这批岗位到底在要什么

勾选一批岗位，立刻得到一份**统计画像**（纯本地运算，零成本、零延迟、离线可用）：

- **薪资分布**：P25 / 中位数 / P75 / 区间，一眼看清这批岗位的真实价位；
- **高频能力排行**：从 JD 原文、职位名、技能标签里抽取技能并归一化统计出现率；
- **职责聚类**：按句首动词归并同类职责，抽出代表句；
- **加分项排行**：哪些「优先考虑」的条件被反复提及。

### 三档匹配矩阵：知道自己强在哪、缺在哪

这是本工具最核心的差异化能力 —— 把你的**档案**（技能 + 项目 + 量化亮点）和 JD 要求做**本地集合运算**，分成三档：

| 档位 | 含义 | 你该怎么做 |
|---|---|---|
| ✅ **已具备** | JD 要求 ∩ 你的技能 | 作为主推优势，放到简历摘要最前面 |
| ⚠️ **有但没写透** | 项目描述里有证据，但技能栏没写 | 改表述、补量化结果 |
| ❌ **明确缺失** | JD 要求 − 你的技能 | 按出现频次（ROI）排序补 |

并给出 **0–100 的匹配度评分**、**逐岗位投递排序**（哪些最值得投）、**「怎么补足」**和**「如何提炼优势」**的具体建议。

> 长尾要求不会吓唬你：只有出现率高的「核心要求」缺失才算真差距。

### 雷区预警：HR 这些话背后是坑

内置 8 类敏感话题的**确定性规则识别**（不依赖模型，不会漏判）：

| 话题 | 为什么是坑 | 应对方向 |
|---|---|---|
| 期望薪资 | 先报价会失去锚点 | 先反问薪资结构，再给区间、上限贴着岗位上限 |
| 当前薪资 | 会被按「涨幅 20–30%」压价 | 只谈整体包区间，把话题拉回期望 |
| 离职原因 | 抱怨前公司 = 减分项 | 正向表达「想做更大量级的业务」 |
| 到岗时间 | 「随时」显得不好卖，「太久」直接出局 | 给确定区间 + 说明交接 |
| 加班强度 | 拒绝出局、答应埋雷 | 先反问真实节奏，表达关键节点可配合 |
| 学历 / 婚育年龄 / 是否海投 | 回答不当放大劣势或踩隐私线 | 一句带过，把话题拉回能力与岗位 |
| 其他 offer | 说太少削弱议价、说太多显得骑驴找马 | 说同方向机会在初筛，强调这家最匹配 |

### 专属话术：开场白、自我介绍、经历钩子、反问清单

基于「JD × 你的档案」生成可直接复制发送的话术，带 **3 种开场白**（亮点前置版 / 稳重版 / 提问式）、**经历钩子**、**反问清单**和**预判追问**。

- 每条开场白**不超过 80 字**，口语化、不报告腔；
- **红线：只用简历里真实存在的事实与数字，绝不虚构经历** —— 并带**自检机制**，一旦话术里出现简历中没有的数据或模板腔，会当场提示。

### 聊天回复建议：把主动权拿回来

在聊天页，插件基于「岗位 JD × 你的档案 × 真实对话」生成回复建议：

- **意图判断**：HR 这句到底在确认什么；
- **3 种策略**：热情 / 专业 / 反问，风格明显不同，每条 ≤ 80 字；
- **可放大的优势**：每条都**附带证据**，证据只能来自你的档案；
- **还差哪些信息没问清**：自动跳过已经聊过的，给一句可直接发送的问法，一键复制；
- **薪资锚定**：只在 HR 问到薪资时给出，数字全部来自岗位本身，不凭空推测；
- 支持**一键填入**聊天输入框（兼容 React 受控组件与 contenteditable），但**发送永远由你点击**。

### 可选 AI 增强：让文案更自然

配置 LLM 后，插件会在**本地规则结果**之上叠加个性化润色：更自然的话术、结合语境的回复版本、以及一段「这批岗位最看重什么 / 你该突出什么 / 最该补什么」的自然语言总结。

> **关键设计：统计与判定永远在本地，LLM 只负责「怎么说」。** 因此 AI 不可用、超时、或返回格式不标准时，你依然能拿到完整的规则结果，最多是表达上降级 —— 不会一片空白。

## 为什么值得一试

- **隐私优先，数据不出浏览器。** 没有账号、没有云端、没有自建服务器，所有数据存在 `chrome.storage.local`。启用 AI 时，JD 与档案片段也只发送到**你自己配置的模型端点**。
- **零配置也能用。** 不填任何 AI 凭证，薪资分布、技能词频、匹配三档、雷区预警、规则话术、规则回复建议全部可用。
- **接你自己的模型，最高可完全离线。** 任意 OpenAI 兼容端点都行，包括本地 Ollama —— 搭配本地模型就是完全离线的求职助手。可分别配置「快模型」（抽取/分类）与「强模型」（话术/建议）。
- **成本可控。** 大量计算走本地规则，token 只花在真正需要语言能力的地方；结构化输出做了**三层兜底**（`response_format` → ```` ```json ```` 代码块 → 首个 `{`），兼容端点返回不标准也不会直接失败。
- **零构建，改完就用。** 原生 JS + HTML + CSS，没有打包、没有依赖、没有 node_modules。读懂源码、按自己的需求魔改都毫无门槛；核心算法还有 `node tests/run.js` 纯函数自测兜底。
- **克制而合规。** **不会**自动打招呼、**不会**自动投递；只做采集与建议，发送动作永远由你本人完成。旁路监听只 `clone` 响应再读取，**不消费原始数据流，页面功能完全不受影响**。

## 快速开始

1. 打开 `chrome://extensions/` → 右上角开启**开发者模式**；
2. 点**加载已解压的扩展程序** → 选择本目录；
3. 打开 https://www.zhipin.com/web/geek/jobs ，**刷新一次**（抓取脚本在 `document_start` 注入）；
4. 点击工具栏图标，右侧弹出侧边栏，即可开始使用；
5. （可选）想用 AI：到「设置」填写 LLM 地址 / 模型 / 凭证 → 点「**测试连接**」并按提示允许域名权限。

> **零构建**：改完代码后，回到 `chrome://extensions/` 点击本插件的刷新按钮即可生效。

## LLM 配置

任何 **OpenAI 兼容**的端点都可以，也可分别指定快/强两个模型（只填一个也可以）：

| 服务商 | 地址示例 |
|---|---|
| DeepSeek | `https://api.deepseek.com` |
| 通义千问 | `https://dashscope.aliyuncs.com/compatible-mode` |
| 火山豆包 | `https://ark.cn-beijing.volces.com/api/v3` |
| 本地 Ollama | `http://localhost:11434`（需允许跨域） |

> 侧边栏的来源是 `chrome-extension://<id>`，模型服务商不会给它放行跨域，因此首次使用需在「测试连接」时**授予该域名权限**（插件采用运行时按需申请，而不是申请全站权限）。若看到 `Failed to fetch`，基本都是这一步没授权。

## 项目结构

```
boss-assistant-v1/
├── manifest.json              # MV3 清单：权限、侧边栏、内容脚本注入
├── package.json               # npm 元数据（零依赖，仅用于发布 GitHub Packages）
├── Makefile                   # 开发与发版命令（make release v0.0.3）
├── README.md / LICENSE        # MIT 协议
├── .github/workflows/
│   └── build-extension.yml    # CI：测试 → 打包 zip → 发布 Packages / Release
├── tests/
│   └── run.js                 # 纯函数自测（node tests/run.js）
└── src/
    ├── net-hook.js            # MAIN world：旁路只读监听 fetch / XHR（全站注入）
    ├── shared.js              # 协议解析 + JD 切分 + 薪资解析（纯函数，面板也复用）
    ├── jobs.js                # 岗位页：抓取编排、限速退避、持久化
    ├── chat.js                # 聊天页：会话上下文采集 + 一键填入输入框
    ├── jobpage.js             # 职位详情页：抓取岗位与 JD 全文
    ├── llm.js                 # OpenAI 兼容客户端（三层 JSON 兜底 + 域名权限）
    ├── profile.js             # 本地档案：文本抽取 + 手填表单
    ├── agents/                # 从服务端移植的纯函数算法（可用 node 验证）
    │   ├── skills.js          # 技能词典、别名归一、年限抽取
    │   ├── batch.js           # 薪资分布 / 技能词频 / 职责聚类 / 加分项排行
    │   ├── matcher.js         # 三档匹配矩阵 + 匹配度评分
    │   ├── analysis.js        # 批次 × 档案 → 优势 / 不足 / 补足 / 排序
    │   ├── script.js          # 规则话术 + 编造数据自检
    │   ├── chatRules.js       # 雷区正则 + 信息清单 + 薪资锚定
    │   └── chatAdvisor.js     # 回复建议契约、规则兜底、prompt 构建与截断
    ├── background/
    │   └── service-worker.js  # 打开侧边栏、转发状态、广播新消息
    └── sidepanel/
        ├── panel.html         # 面板结构
        ├── panel.css          # 面板样式
        └── panel.js           # 面板逻辑：岗位/话术/档案/分析/设置
```

**分层一句话看懂**：`net-hook`（抓）→ `jobs / chat / jobpage`（编排与上下文）→ `agents/*`（纯函数算法）→ `sidepanel`（UI）→ `llm.js`（可选 AI）。统计与判定全部收敛在 `agents/*`，因此改算法、加规则、写测试都不需要碰 UI，也无需任何构建。

## 设计要点

- **旁路只读**：监听 `fetch` / `XHR` 时只 `clone()` 响应再读取，绝不消费原始流；被动捕获不产生任何额外请求，主动抓 JD 由调用方严格限速。
- **内容优先的端点识别**：以响应内容判断数据类型（而不是硬匹配 URL），因此在推荐页与搜索页都能稳定工作。
- **页面状态全落盘**：MV3 的 content script 会随页面跳转销毁，岗位与解析结果因此持久化到本地存储。
- **权限最小化**：默认只申请 `zhipin.com`，LLM 域名在用户点击「测试连接」时按需申请。
- **AI 永远可降级**：所有 LLM 调用失败都会回落到规则结果，并给出人话报错。

## 构建与发布

项目**零构建**，无需打包即可直接加载。GitHub Actions 会产出两种可分发产物：

- **推送到 `main` 或发起 PR**：自动跑 `node tests/run.js` 并打包，zip 作为 **Artifact** 供下载；
- **推送 `v*` 标签**：测试通过后同时发布 **GitHub Packages**（npm 包）与 **GitHub Release**（zip 附件）—— 两条分发通道一起更新；
- **手动触发**：在 Actions 页面选 `Build Chrome Extension` → `Run workflow` 即可随时打包。

`manifest.json` 的 `version` 是唯一版本来源，CI 会把它同步到 npm 包版本，**不需要手动改 `package.json`**。

### 安装方式

**方式一：直接下载（推荐给普通用户）**
到仓库 **Releases** 页面下载 `boss-assistant-vX.Y.Z.zip`，解压后在 `chrome://extensions/` 里「加载已解压的扩展程序」选择该目录。

**方式二：从 GitHub Packages 拉取（推荐给开发者）**
GitHub Packages 即使公开包也需要鉴权，先配置源与 Token（PAT 需含 `read:packages`），再安装：

```bash
npm config set @ytfei:registry https://npm.pkg.github.com
npm config set //npm.pkg.github.com/:_authToken <YOUR_GITHUB_TOKEN>
npm install @ytfei/boss-assistant
```

装好后把 `node_modules/@ytfei/boss-assistant` 目录作为「已解压的扩展程序」加载即可（内含 `manifest.json` 与 `src/`）。也可以直接在仓库 **Packages** 页面下载 tarball。

### 本地打包 / 发版

仓库自带 `Makefile`，`make help` 可查看全部命令：

```bash
make help       # 查看所有目标
make test       # 跑纯函数自测
make package    # 本地打出 boss-assistant.zip（可直接加载）
make version    # 显示当前版本
```

**发版只需一条命令** —— 自动改版本号（`manifest.json` + `package.json`）、提交、打 tag 并推送：

```bash
make release v0.1.1
```

执行流程：校验版本格式与工作区是否干净 → 跑自测 → 改写版本号 → 提交 `chore(release): v0.1.1` → 打标签 → 推送到 `origin`。推送后 CI 即自动发布 GitHub Packages 与 Release。

> 发版前请确保工作区干净（`git status` 无改动），否则会中止并提示，避免把无关改动卷进发版提交。
> 若推送失败（网络 / 权限问题），版本提交与标签已在本地生成，补一条 `git push origin main --follow-tags` 即可。
> 重复推送同一版本时，Packages 发布会自动跳过，不会因为「版本已存在」而让任务变红。
